# Дизайн переключаемого распознавания GigaAM / Whisper

Дата: 2026-07-20

## Цель

Сделать GigaAM основной моделью локальной диктовки, сохранив `faster-whisper` как вручную выбираемый резерв. Основной сценарий остаётся прежним: пользователь включает запись по `F9`, говорит короткую фразу, выключает запись и получает распознанный текст в активном приложении.

## Границы MVP

В MVP входят:

- GigaAM-v3 `v3_e2e_rnnt` как модель по умолчанию;
- переключатель движка `GigaAM` / `Whisper` в окне настройки;
- сохранение выбранного движка в `config.json`;
- единый интерфейс распознавания для всех текущих проходов: промежуточного, фонового уточнения и финального;
- понятная ошибка загрузки выбранного движка без скрытой автоматической смены модели;
- автоматические тесты адаптеров и конфигурации;
- сквозная проверка GigaAM на реальном WAV-файле.

В MVP не входят long-form распознавание, параллельная загрузка двух моделей, автоматический выбор модели по языку и автоматическое переключение на Whisper при ошибке GigaAM.

## Выбор модели

Основная модель — GigaAM-v3 `v3_e2e_rnnt`. Она предназначена для коротких аудиофрагментов до 25 секунд и возвращает текст с пунктуацией и нормализацией. Текущий жёсткий предел буфера приложения равен 14 секундам, поэтому long-form API и зависимости `pyannote` не нужны.

`v3_e2e_ctc` не выбирается из-за более слабого качества относительно RNNT. Обычный `v3_rnnt` не выбирается, потому что для пользовательской диктовки потребовался бы отдельный этап расстановки пунктуации.

## Архитектура

Новый модуль `stt_backend.py` инкапсулирует различия движков.

- `create_stt_backend(cfg)` создаёт только выбранный движок.
- `GigaAMBackend` загружает `gigaam.load_model("v3_e2e_rnnt")` на CUDA при её доступности, иначе на CPU.
- `WhisperBackend` сохраняет существующую загрузку `WhisperModel`, включая переход на CPU при ошибке CUDA.
- Оба адаптера предоставляют один метод `transcribe(audio, quality, force_vad=False) -> str`, где `audio` — монофонический `numpy.float32` с частотой 16 кГц, а `quality` принимает значения `interim` или `final`.
- Whisper сопоставляет `quality` с существующими `beam_interim` / `beam_final`, `vad_filter` и `initial_prompt`; `force_vad=True` сохраняет принудительный VAD в пути разрезания переполненного буфера.
- GigaAM использует один и тот же инференс для обоих режимов: неподдерживаемые параметры Whisper ей не передаются.

Существующий `model_lock` продолжает сериализовать обращения к GPU. Все прямые вызовы `model.transcribe(...)` в `dictate_realtime.py` заменяются вызовами общего адаптера, который сразу возвращает строку.

## Аудиопоток GigaAM

GigaAM принимает путь к аудиофайлу, а приложение хранит запись в памяти. На каждый вызов адаптер:

1. ограничивает значения `numpy` диапазоном `[-1, 1]`;
2. преобразует их в моно PCM16;
3. записывает временный WAV с частотой 16 кГц стандартным модулем `wave`;
4. вызывает `model.transcribe(path)`;
5. извлекает текст из `TranscriptionResult.text` с совместимым резервом для строкового результата;
6. удаляет временный файл в блоке `finally`, включая путь ошибки.

Текущие ресемплинг, VAD, обрезка тишины и фильтр галлюцинаций остаются без изменения. `faster-whisper` остаётся зависимостью, потому что используется и как резервный движок, и как источник существующего Silero VAD.

## Конфигурация и интерфейс

В конфигурацию добавляются:

- `stt_engine`: `"gigaam"` по умолчанию или `"whisper"`;
- `gigaam_model`: `"v3_e2e_rnnt"` по умолчанию.

Существующее поле `model_size` продолжает задавать размер Whisper и не мигрируется. Старые `config.json` без `stt_engine` автоматически получают GigaAM через значения по умолчанию.

В окне настройки появляется список `Recognition engine`. При GigaAM поле модели показывает `v3_e2e_rnnt`; при Whisper оно показывает существующий список размеров Whisper. Выбор сохраняется без удаления настроек неактивного движка, поэтому обратное переключение не требует повторной настройки.

## Зависимости и запуск

В `requirements.txt` добавляется GigaAM с extra `torch` из официального GitHub-репозитория тем же способом, который уже проверен в `jitsi-meet-recordings`, но без long-form extra. Уже установленный совместимый `torch` переиспользуется, а отсутствующий `torchaudio` устанавливается в согласованной версии. `ffmpeg` должен быть доступен в `PATH`, как требует GigaAM.

При первом запуске GigaAM скачивает веса в пользовательский кэш. В журнале запуска выводятся выбранные движок, модель и устройство. Приложение не загружает резервную модель и не занимает под неё память.

## Ошибки

- Если пакет или внешняя системная зависимость отсутствует, запуск завершается с сообщением, какая зависимость нужна и как выбрать Whisper в настройках.
- Если загрузка GigaAM на CUDA не удалась, адаптер повторяет загрузку на CPU; это смена устройства внутри выбранного движка, а не скрытая смена движка.
- Если инференс отдельной фразы завершился ошибкой, временный файл удаляется, ошибка записывается в журнал, а приложение продолжает принимать следующую фразу.
- Пустой результат обрабатывается существующим сценарием `no speech` и не вставляется в активное окно.

## Проверка

Автоматические тесты проверяют:

- GigaAM выбран по умолчанию, а старый конфиг остаётся совместимым;
- фабрика создаёт запрошенный движок;
- GigaAM получает корректный WAV 16 кГц PCM16 и возвращает текст;
- временный WAV удаляется после успеха и после исключения;
- Whisper продолжает получать прежние параметры для промежуточного и финального режимов;
- окно настройки сохраняет выбранный движок и соответствующую модель;
- `dictate_realtime.py` не содержит прямых вызовов модели в пользовательских путях.

Сквозная проверка запускает реальную GigaAM-v3 `v3_e2e_rnnt` на доступном тестовом WAV из `jitsi-meet-recordings` либо на локально записанном коротком WAV, подтверждает непустой русский текст и успешное завершение процесса. Отдельно выполняется полный текущий набор тестов с выбранным резервом Whisper.

## Критерии готовности

Работа завершена, когда:

- новый конфиг по умолчанию запускает GigaAM;
- переключение на Whisper выполняется через окно настройки и не требует изменения кода;
- оба адаптера проходят автоматические тесты;
- реальная GigaAM загружена и дала непустую транскрипцию короткого WAV;
- текущие тесты проекта проходят без регрессий;
- основной запуск приложения доходит до состояния `[init] Ready` с выбранным движком.
